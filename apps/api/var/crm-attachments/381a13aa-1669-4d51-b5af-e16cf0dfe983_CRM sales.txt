You are a senior full-stack engineer and product designer. Build a production-ready SALES CRM (web app) that replaces Zoho CRM for our sales process only. Do NOT build distributors/projects/full ERP. Scope = Company → Lead → Opportunity → Quote → OVF → Deal Won, plus My Jobs approvals, Contacts, Products, role-based access.

============================================================
A. PRODUCT PRINCIPLES
============================================================
1. Repositories: global list views for Company, Contacts, Opportunities, Leads, Quotes, OVF, Products — searchable across the org — BUT child records must be created FROM the parent Company (or from Opportunity/Quote blueprint where specified) so account/address/entity data auto-fetches.
2. Do NOT allow standalone “Create Opportunity” from Opportunities home. Opportunity is created ONLY via Lead → “Convert to Opportunity”.
3. Do NOT allow Create Quote until Opportunity has completed OEM Quotation Received + Attach OEM Quote.
4. “Lost Lead” / “Lost Deal” is available at almost every stage (not Closed Won). Won only happens at the end as Deal Won.
5. Approvals: merge Zoho’s dual “send email” + “send for approval” into ONE action: “Send for approval to {Team}”. This creates a My Jobs task, sends email/in-app notification, and can lock the record until approved/rejected.
6. Prefer ONE deal timeline / breadcrumb UI so users don’t hop Quote ↔ Opp ↔ OVF blindly. Still keep separate modules as repositories.
7. Currency: INR (₹). Support GST/HSN where quote line items need it.
8. Demo-first: implement full happy path + Lost exits + My Jobs approve/reject. Deep approval hierarchy can be stubbed with roles but margin lock rules MUST work.

### 3) OPPORTUNITY — post convert
No manual create from module +. Show current state always.

Initial actions (show as blocks):
- Attach BoQ
- Attach SoW
- Lost Lead (always)

#### 3a BoQ path (product / infra / cloud)
- Attach BoQ: upload ANY file type (xlsx, doc, pdf, image, screenshot)
- Then: “Send for approval to Pre-sales team” (single merged step)
- Pre-sales gets My Jobs task → Approve/Reject
- Sales gets notification; record unlocks to next options
- Wait/block further commercial steps that depend on BoQ until approved (or allow parallel SoW design — prefer sequential for demo)

#### 3b SoW path (services — Cashy/project team)
- Attach SoW (manpower, deployment, implementation, managed services, etc.)
- Send for approval to Project team
- SKIP SoW if deal is product-only
- If BOTH product + services: complete BoQ then SoW then continue

#### 3c Deal Registration
- Action: Deal Reg
- Fields: DR Number OR “NA” (allow alphanumeric/text — OEM DR numbers can be words)
- Optional amount if needed

#### 3d OEM Quotation Received — HARD GATE
- Transition: OEM Quotation Received (Yes/No) + Lost Lead
- If No → stay on same step (cannot proceed)
- If Yes → Attach OEM Quote (file required) + Lost Lead
- ONLY after OEM quote attached → show Create Quote + Lost Lead

Business rule: Sales never invents cost price. Cost comes from OEM/vendor quote OR from project team for SoW services. We are middle/channel.

  Example: cost 2000, margin 10% → sell 2200; OR enter sell 2200 with cost 2000 → margin 10%
- GST %, Total GST, Total Amount with GST

Quote totals:

- Grand Total including Freight

Additional:

- Description

- BOQ Attachment (optional on quote)

QUOTE BLUEPRINT after save:
1. Send Quote to Internal Team for Approval  (ONE merged step; creates My Jobs + notify)
2. Margin hierarchy gate:
   - Hardware/Software minimum margin: 7%
   - Services (any type: managed, manpower, deployment, implementation): 20%
   - If margin ≤ threshold (including “up to” threshold) → LOCK quote → Management approval required
   - If margin ABOVE threshold → Sales can “Approve Internally”
   - Mixed HW+Services: apply the stricter/max rule (if HW below 7% even when services high → still lock)
3. Quotation Approved Internally
4. Send Quotation to Customer
   - THIS IS INTERNAL STAGE ONLY — do not actually email customer/OEM from CRM in this step (stage marker)
5. Then transitions:
   - Negotiation → loop (stay/repeat customer stage)
   - Follow Up → loop
   - Quote Accepted → Yes/No confirm → proceed
   - Lost Deal still available

### 5) AFTER QUOTE ACCEPTED → back on OPPORTUNITY
Actions:
- Attach PO (customer purchase order file)
- Lost Deal (still possible even after accept)

Then:
- Send for approval to Accounting (merge email+approval; Accounts role / Namit)
- Record LOCKS until PO approved
- Strong pending-approval notification

### 6) OVF MODULE — create from Quote after PO approved
OVF must be LOCKED/unavailable until PO is attached & approved on Opportunity.
On create: auto-fetch from Opportunity/Quote/Company/Entity:
Customer Name, Billing/Shipping addresses, Quote Name, Quote No, Account, Opportunity*, Owner, Entity fields, products/qty from quote (NOT quote unit prices for customer PO lines — prices entered manually against PO).

OVF fields:
- Ovf sent to SCM team (system Yes/No, locked; flips on share)
- Technology Segment* (multi-select picklist + Others) 
- Sub Technology Segment* (depends on segment; multi + Others)
- PO Number*
- Delivery Period / validity date*
- Installation/Service Details
- Contact persons / countries (billing vs shipping)
- Opportunity* (lookup)
- Approval Status (locked/system)
- Total Margin Amount / Total Margin %
- Additional Charges (₹), Freight Charges (₹)
- Vendor Payment Terms (days)
- Customer Payment Terms (days)
- Finance Cost (%): auto from payment gap
  Rule of thumb: 0.5% per 15 days gap (30d≈1%, 45d≈1.5%, 2.5 months≈2.5%). If vendor due earlier than customer collection, finance cost increases and should feed margin calc.
- Customer PO line prices: MANUAL entry (qty fetched; price not blindly fetched from quote because PO price may change after negotiation)
- Attach Customer PO* (mandatory)
- Vendor section: same products implied; enter vendor qty/price; Attach Vendor Quote*
- Approval Status workflow

OVF BLUEPRINT:
1. Send OVF for Approval (merged single step)
2. On approve → “OVF Share to SCM Team”
3. Then Deal Won (no Lost at this terminal share step)
4. On Deal Won click: MANDATORY prompt for Deal Won Amount (people forget — force field)
5. Sales CRM path ENDS at Share to SCM / Deal Won

Future gap (note in code comments / TODO): if deal includes services/SoW, also route to Project/services team (not only SCM). Not required for first demo but design hooks.
